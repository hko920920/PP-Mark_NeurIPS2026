# PP-Mark

**PP-Mark: Provable and Publicly Verifiable Watermarking for Generative AI**<br>
Hankyeong Ko and Taehoon Kim<br>
Graduate School of Virtual Convergence, Sogang University<br>
NeurIPS 2026 · Accepted as a poster

PP-Mark combines a context-bound latent watermark with an SP1 receipt. **Score**
is the claim-conditioned statistical detection mode (`--mode detect`). **Accept**
additionally verifies the image-bound receipt against a trusted producer-key
commitment (`--mode attest`). An image and its public metadata are the verifier
inputs. The two modes provide different assurance levels.

This source release includes the post-submission implementation updates and the
SP1 v6.3.1 streaming-v2 path. The Python import name remains `ppmark_v03` for
compatibility. See [implementation](docs/architecture.md),
[evaluation instructions](docs/REPRODUCE.md), and
[external models](docs/MODELS.md).

## Install

Use a Linux/WSL checkout, Python 3.10 or 3.11, and an NVIDIA GPU for image
generation/inversion. Clone the repository, then run the remaining commands
**from the repository root**.
The supported distribution is a source checkout with an editable installation;
keep `tables/`, the JSON configurations, and `sp1/` beside the Python source.

```bash
git clone https://github.com/hko920920/PP-Mark_NeurIPS2026.git
cd PP-Mark_NeurIPS2026
python3 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip setuptools wheel
python -m pip install torch==2.5.1 torchvision==0.20.1 \
  --index-url https://download.pytorch.org/whl/cu121
python -m pip install -r requirements.txt
python -m pip install --no-deps -e .
```

Optional evaluation dependencies:

```bash
python -m pip install -r requirements-eval.txt
```

Install the SP1 v6.3.1 toolchain, `protoc`, and a C/C++ compiler as described in
[sp1/README.md](sp1/README.md). Then build one proving backend:

```bash
bash scripts/build_sp1_h100.sh cuda
# CPU receipt proving is also supported: bash scripts/build_sp1_h100.sh cpu
```

The CPU option applies to SP1 proving. The current image-generation CLI still
uses CUDA. Pretrained diffusion weights are downloaded separately; see
[model identifiers](docs/MODELS.md).

## Generate and verify one image

Create a producer key locally and retain its public commitment as the trust
anchor for this example. The secret is stored outside the public artifact folder.

```bash
python - <<'PY'
from pathlib import Path
from ppmark_v03.keys import generate_keypair
from ppmark_v03.attestation import producer_key_commitment
secret_file = Path("private_keys/producer.hex")
secret_file.parent.mkdir(parents=True, exist_ok=True)
if secret_file.exists():
    raise SystemExit("A producer key already exists; reuse it or choose another path.")
secret = generate_keypair().secret_bytes()
secret_file.write_text(secret.hex() + "\n", encoding="ascii")
anchor = Path("outputs/trust/producer_commitment.txt")
anchor.parent.mkdir(parents=True, exist_ok=True)
anchor.write_text("0x" + producer_key_commitment(secret).hex() + "\n", encoding="ascii")
PY

SP1_PROVER=cuda SP1_PROOF_MODE=core \
python -m ppmark_v03.cli prover \
  --config config_alpha4_k1000.json \
  --prompt "A red bicycle beside a stone wall" \
  --secret-file private_keys/producer.hex \
  --output outputs/demo
```

Use `SP1_PROVER=cpu` if you built the CPU host. `core` is the existing default
receipt mode used by the implementation; other proof modes and their scope are
described in the [SP1 notes](sp1/README.md).

Score verification:

```bash
python -m ppmark_v03.cli verifier \
  --config config_alpha4_k1000.json \
  --metadata outputs/demo/metadata.json \
  --image outputs/demo/watermarked.png \
  --mode detect \
  --tau-file tau_fpr1_alpha4_sd21.json \
  --ddim-device cuda --ddim-dtype float32 --ddim-steps 100
```

Accept verification of the original artifact:

```bash
SP1_PROVER=cpu python -m ppmark_v03.cli verifier \
  --config config_alpha4_k1000.json \
  --metadata outputs/demo/metadata.json \
  --image outputs/demo/watermarked.png \
  --mode attest \
  --expected-key-commitment "$(cat outputs/trust/producer_commitment.txt)" \
  --tau-file tau_fpr1_alpha4_sd21.json \
  --ddim-device cuda --ddim-dtype float32 --ddim-steps 100
```

The example trusts a key generated by the local producer. In deployment, obtain
the expected commitment through your trusted producer registry or another
authenticated channel. Metadata alone does not establish producer trust.
Keep producer keys and prover witnesses private. The default successful prover
removes the serialized witness; `--skip-proof` and debug retention leave private
artifacts and do not provide an accepted proof.

The supplied thresholds are the frozen paper/rebuttal reference values, not a
fresh calibration of this release: `tau_fpr1_alpha4_sd21.json` for SD2.1 and
`tau_fpr1_alpha4_sdxl.json` for SDXL. Preserve the documented evaluation
conditions for comparisons. New model/configuration combinations need their own
calibration; `scripts/calibrate_threshold.py` derives one from clean-image
scores at a target FPR, and `datasets/calibration_recipe.json` records how the
reported prompt collections were selected. An SDXL configuration is included as
`config_alpha4_k1000_sdxl.json`; SDXL inversion requires `bfloat16`, because
`float16` silently collapses the recovered latent to zero.

## Experiments

The [evaluation guide](docs/REPRODUCE.md) describes input formats and commands for:

- claim-conditioned detection and transformation evaluation;
- generation of the transformed collections, and threshold calibration;
- sequential crop–resize–JPEG evaluation;
- Bare-Sig and Context-Sig controls;
- the white-box PGD forgery attack against Score;
- BRISQUE, KID, and CLIP comparisons;
- SP1 proving/verification timing.

Generate images with the provided code or supply your own evaluation collection.
The tools accept image/metadata paths through JSONL manifests. Pretrained model
weights are downloaded separately as described in the model guide.

The forgery attack targets the Score statistic only. It cannot produce an SP1
receipt, so a forged image fails Accept verification whatever its Score; the
evaluation guide shows how to confirm that separation on the attack's output.
