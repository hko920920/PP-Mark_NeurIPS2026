# SP1 v6.3.1, protocol v2

The host verifies the receipt and byte-compares its public values with the
expected statement. The production host accepts the streaming-v2 relation.

- P1 reconstructs context/key binding and producer-key commitment.
- P2 commits the complete ordered sampled trace and index set.
- P3 derives image-specific challenges and the opening digest.
- P4 reconstructs the RS bits, inverse-CDF Gaussian values and normalized
  fixed-point embedding relation at the selected opening positions K.

The witness is a separate prover input. The explicit verifier inputs are the
public statement and receipt. The SDK proof mode determines its additional
privacy and compression properties; the `core` timing/default mode should not
be interpreted as a demonstrated zero-knowledge deployment configuration.

## Build

Use Linux/WSL, the SP1 v6.3.1 toolchain (`sp1up --version 6.3.1`), Rust, a C/C++
compiler and `protoc` including Google protobuf headers. Follow the
[SP1 toolchain documentation](https://docs.succinct.xyz/) for installation and
the GPU prover's system prerequisites. From the repository root:

```bash
bash scripts/build_sp1_h100.sh cuda
# or, for CPU receipt proving:
bash scripts/build_sp1_h100.sh cpu
```

The binary is `target/sp1/release/sp1-genguard-host`. The source pins release LTO,
SDK version and dependency lock. The historical streaming ELF was 381,384 bytes,
SHA-256 `1a9eb1a3b100ac7de792cb44865946d44301330574922a187c7ce1b237bb1459`.
Toolchain or source changes can change the ELF and verifying key.

## Receipt commands

Use public/witness files generated by the image CLI. A model-free input can also
be produced for implementation diagnostics; it is not a generated SD image:

```bash
python scripts/build_sp1_attest_fixture.py \
  --output outputs/fixture --commitment-scheme streaming \
  --width 64 --height 64 --sample-count 1000 --opening-k 32

SP1_PROVER=cpu SP1_PROOF_MODE=core \
target/sp1/release/sp1-genguard-host prove \
  --public outputs/fixture/attestation_statement.json \
  --witness outputs/fixture/private_witness.json \
  --receipt outputs/fixture/attest_receipt.bin

SP1_PROVER=cpu target/sp1/release/sp1-genguard-host verify \
  --public outputs/fixture/attestation_statement.json \
  --receipt outputs/fixture/attest_receipt.bin
```

Receipt-only verification does not perform the image's Score decision or an
external producer-trust check. Use the main CLI's `--mode attest` for that flow.

`SP1_PROOF_MODE` accepts `core` (default), `compressed`, `plonk`, and `groth16`.
The standard Python prover deletes its serialized witness after a successful
proof unless private-debug retention is requested. Never use the diagnostic
fixture key as a producer key.

## Timing

`host/examples/timing_campaign.rs` records setup, execution, proving and
verification separately; `host/examples/cycle_compare.rs` contains historical
v1/v2 comparisons. Build an example with `cargo build --release --manifest-path
sp1/Cargo.toml -p sp1-genguard-host --example timing_campaign --features cuda`.
Use the explicit arguments documented in [the reproduction guide](../docs/REPRODUCE.md).
Report proof mode, hardware, SDK and whether setup is included with timing results.
